# SKU 分组 OWLv2 提示词生成设计

## 目标

SKU 批量管理页中，勾选的 SKU 作为一个对比组，只调用一次 Ark VLM。模型同时观察同类商品的主图和正常货位图，为组内每个 SKU 生成可区分的英文 OWLv2 提示词。

该设计解决逐条生成时提示词过于泛化的问题，例如同品牌不同口味饮料能从主色、口味文字和包装图案中互相区分。

## 输入与组装

- 用户在 SKU 批量管理页勾选 2 到 8 个 SKU 后点击生成。
- 每个 SKU 必须同时具备：`reference_image_path` 指向的 SKU 主图，以及该 SKU 的一张正常货位 ID 图。
- 缺少任一图片的 SKU 不进入本次对比组；接口返回其 SKU 名称和缺失原因。
- 服务端将每个有效 SKU 组装为固定尺寸的双图单元：左侧为 SKU 主图，右侧为正常货位 ID 图。
- 单元顶部的纯色标题栏显示连续序号和 SKU 名称；标题栏不覆盖任一商品图像。
- 所有单元拼成一张对比图后，作为唯一图片输入发送给 Ark VLM。

## Ark 请求与返回

请求明确要求模型：

- 对比同组 SKU，识别每项相对其他项的可见差异；
- 每项输出一个短英文 OWLv2 检测提示词；
- 优先使用品牌、口味、包装主色、包装图案和可见标签文字等稳定特征；
- 避免只输出泛化品类词；
- 只返回严格 JSON，按标题栏序号映射到提示词。

服务端校验 JSON、序号完整性和每条提示词的现有长度/字符规则。无效响应不修改页面草稿，并返回可读错误。

## 页面行为

- 生成结果按 SKU 回填到管理页的提示词草稿中，覆盖这些 SKU 此前的草稿值。
- 结果尚未写入数据库；只有用户点击“保存全部修改”才持久化。
- 页面提示本次生成数量和被跳过 SKU 的具体原因。
- 单次请求的有效 SKU 超过 8 个时，接口拒绝并提示拆分为多个对比组，避免拼图过密、模型判断下降。

## 范围

仅修改 SKU 批量管理的 `/api/skus/prompts/generate` 语义及其 VLM 辅助函数。人工批量录入审核页的单 SKU 提示词草稿生成保持原行为。

## 验证

- 单元测试覆盖：完整组只有一次 VLM 调用、编号到 SKU 的正确映射、缺图 SKU 被跳过、超过 8 个被拒绝、无效 JSON 不产生草稿。
- 前端构建验证按钮的结果提示与保存前草稿状态。
